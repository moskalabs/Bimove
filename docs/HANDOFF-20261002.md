### `93e1022` 상세 — 이것만 구조가 좀 크다

버전 패널이 localStorage 만 읽었다. 기기를 바꾸거나 캐시를 지우면 버전 기록이 통째로 사라졌다.

파보니 **세 군데가 동시에 비어 있었다:**
1. `project_versions` 테이블의 마이그레이션이 아예 없었다 — `src/lib/supabase.ts` 에 `DBProjectVersion` 타입만 있었다
2. `fetchProjectVersions` / `saveProjectVersion` / `deleteProjectVersion` 은 **호출부가 0곳**인 죽은 코드였다
3. 패널은 로컬 목록만 그렸다

그래서 네 조각을 한꺼번에 넣었다 — 올리기 / 읽기 / 삭제 / 이름변경. 하나만 빠지면 동작이 어긋난다
(서버 삭제가 없으면 지운 버전이 다음에 패널 열 때 그대로 되살아난다).

새로 생긴 파일:
- `src/lib/versionSync.ts` — 로컬+서버 병합 규칙. supabase 를 직접 import 하지 않고 deps 로 받는다 (네트워크 없이 테스트 가능). `conflictBackup.ts` 와 같은 방식.
- `supabase/migrations/20261002_project_versions.sql`
- `src/__tests__/lib/versionSync.test.ts` (12개)
- `src/__tests__/components/versionHistoryPanel.test.tsx` (11개)

알아두면 좋은 설계 결정:
- **목록은 메타데이터만 받는다** (`id, label, created_at`). 스냅샷 하나가 수 MB 라서 `select('*')` 로 30개를 받으면 패널 여는 것만으로 수십 MB 를 내려받는다. 스냅샷은 복원/비교할 때 `fetchProjectVersionSnapshot(versionId)` 로 그 하나만 받는다.
- **실패를 삼키지 않는다.** 예전 `fetchProjectVersions` 는 `const { data } = await ...` 로 `error` 를 버렸다. 지금은 전부 `error` 를 받아 throw 하고, 패널이 배너를 띄운다. 단 환경변수가 없으면 (`supabaseConfigured === false`) 조용히 넘어간다 — 로컬 개발에서 겁주는 배너를 안 띄우려고.
- **라벨 충돌은 로컬 우선.** 이름 변경은 양쪽에 같이 쓰니 갈리는 건 오프라인 수정뿐이고, 그때는 로컬이 더 최신일 확률이 높다.
- `created_at` 이 깨져 `timestamp` 가 `NaN` 인 버전은 목록에서 뺀다. 안 빼면 정렬이 무너지고 화면에 "Invalid Date" 가 찍힌다.

**덤으로 고친 실버그:** `src/lib/supabase.ts` 가 환경변수 없을 때 `createClient('')` 로 **import 시점에** 던졌다
(`supabaseUrl is required.`). 그래서 supabase 를 간접적으로라도 거치는 화면이 통째로 백지가 됐다
(`RBar → VersionHistoryPanel → supabaseSync → supabase`). 자리채움 값으로 만들고 실제 요청 여부는
`supabaseConfigured` 로 가린다. — 이게 `rbarPropsPanel.test.tsx` 가 수집 단계에서 터지던 원인이기도 했다.
